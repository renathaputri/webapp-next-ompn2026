## 2. ATURAN KERAS UNTUK AGEN CODING

1. **Waktu hanya dipercaya dari server.** Jangan pakai jam browser untuk buka/tutup pendaftaran, mulai/akhir ujian, atau sisa waktu. Timer client hanya tampilan; sumber kebenaran adalah `attempt.endsAt` di DB.
2. **Simpan semua waktu dalam UTC**, tampilkan dalam WIB.
3. **`correctIndex` dan `explanation` TIDAK BOLEH ikut terkirim ke client** lewat query, server action, atau API apa pun selain halaman pembahasan yang lolos pengecekan akses (bagian 8). Gunakan `select` eksplisit. Buat dua helper: `getQuestionsForExam()` (tanpa kunci) dan `getQuestionsForReview()` (dengan kunci, dijaga).
4. **Semua otorisasi di sisi server.** Middleware hanya lapisan tambahan.
5. **Peserta hanya boleh membaca data miliknya.** Setiap query peserta memfilter `userId` dari sesi, bukan dari URL/body.
6. **Penilaian hanya dihitung di server**, dalam satu fungsi murni `gradeAttempt()` yang punya unit test.
7. **Semua operasi tulis penting idempotent** (submit, autosave, publish).
8. **Setiap perubahan penting oleh admin dicatat** di `AuditLog`.
9. **Semua HTML dari editor wajib disanitasi di server** (saat simpan dan saat render). Tidak ada `dangerouslySetInnerHTML` tanpa sanitizer.
10. Jangan menambah fitur di luar PRD tanpa diminta. Keputusan yang belum jelas: pakai bagian "ASUMSI" dan tulis di README.
11. Tulis kode kecil-kecil per fase, jalankan `tsc` dan lint tiap selesai satu fitur.
12. **Jangan hardcode** jumlah soal, jumlah pilihan, atau durasi. Semua dari data `Exam`.

## 4. SKEMA DATABASE (Prisma)

```prisma
generator client { provider = "prisma-client-js" }
datasource db {
  provider  = "postgresql"
  url       = env("DATABASE_URL")
  directUrl = env("DIRECT_URL")
}

enum Role          { PARTICIPANT ADMIN }
enum ExamStatus    { DRAFT SCHEDULED CLOSED }   // "berlangsung" dihitung dari jadwal, tidak disimpan
enum AttemptStatus { IN_PROGRESS SUBMITTED }
enum SubmitReason  { MANUAL TIMEOUT ADMIN }

model User {
  id                 String    @id @default(cuid())
  participantCode    String?   @unique          // OMPN26-0001, otomatis saat daftar
  name               String
  email              String    @unique
  whatsapp           String    @unique          // sudah dinormalisasi (628xx), nomor milik peserta sendiri
  school             String                     // teks asli untuk tampilan
  schoolNormalized   String                     // huruf kecil, spasi dirapikan; untuk pencarian/filter/rekap
  city               String
  levelId            String?
  level              Level?    @relation(fields: [levelId], references: [id])
  passwordHash       String
  mustChangePassword Boolean   @default(false)
  passwordChangedAt  DateTime?                  // JWT yang terbit sebelum waktu ini tidak valid
  role               Role      @default(PARTICIPANT)
  isActive           Boolean   @default(true)
  failedLogins       Int       @default(0)
  lockedUntil        DateTime?
  consentAt          DateTime?                  // waktu setuju kebijakan privasi
  createdAt          DateTime  @default(now())
  registrations      Registration[]
  auditLogs          AuditLog[]
  @@index([schoolNormalized])
}

model Level {                       // SD/MI, SMP/MTs, SMA/MA/SMK
  id        String  @id @default(cuid())
  code      String  @unique         // SD | SMP | SMA
  name      String
  sortOrder Int     @default(0)
  users     User[]
  exams     Exam[]
}

model Subject {
  id       String  @id @default(cuid())
  name     String  @unique
  isActive Boolean @default(true)
  exams    Exam[]
}

model Exam {                        // 1 ujian = 1 kombinasi jenjang + mapel, semua parameter ditentukan admin
  id               String     @id @default(cuid())
  levelId          String
  subjectId        String
  level            Level      @relation(fields: [levelId], references: [id])
  subject          Subject    @relation(fields: [subjectId], references: [id])
  title            String
  durationMinutes  Int                           // diatur admin
  questionCount    Int                           // diatur admin
  optionCount      Int                           // diatur admin, 2..5, SAMA untuk semua soal dalam ujian ini
  startAt          DateTime?                     // wajib terisi sebelum SCHEDULED
  endAt            DateTime?                     // wajib > startAt
  shuffleQuestions Boolean    @default(false)
  status           ExamStatus @default(DRAFT)
  resultsPublished Boolean    @default(false)
  discussionOpen   Boolean    @default(false)
  isActive         Boolean    @default(true)
  questions        Question[]
  registrations    Registration[]
  @@unique([levelId, subjectId])
}

model Question {
  id           String  @id @default(cuid())
  examId       String
  exam         Exam    @relation(fields: [examId], references: [id], onDelete: Cascade)
  number       Int                                // 1..questionCount
  text         String                             // HTML dari Tiptap (boleh gambar + rumus), disanitasi
  options      Json                               // array string HTML, panjang == exam.optionCount (tanpa gambar)
  correctIndex Int                                // 0-based, harus < optionCount. JANGAN dikirim ke client
  explanation  String                             // HTML (tanpa gambar, boleh rumus). JANGAN dikirim ke client
  answers      Answer[]
  @@unique([examId, number])
}

model Registration {
  id        String   @id @default(cuid())
  userId    String
  examId    String
  user      User     @relation(fields: [userId], references: [id])
  exam      Exam     @relation(fields: [examId], references: [id])
  createdAt DateTime @default(now())
  attempt   Attempt?
  @@unique([userId, examId])
}

model Attempt {                     // satu registrasi = maksimal satu attempt
  id              String        @id @default(cuid())
  registrationId  String        @unique
  registration    Registration  @relation(fields: [registrationId], references: [id])
  startedAt       DateTime      @default(now())
  endsAt          DateTime                       // = min(startedAt + durasi, exam.endAt)
  submittedAt     DateTime?
  status          AttemptStatus @default(IN_PROGRESS)
  submitReason    SubmitReason?
  correctCount    Int?
  score           Decimal?      @db.Decimal(5, 2)
  durationSeconds Int?                           // lihat 6.5 untuk aturan TIMEOUT
  questionOrder   Json?                          // array questionId (jika exam.shuffleQuestions)
  answers         Answer[]
}

model Answer {
  id            String   @id @default(cuid())
  attemptId     String
  questionId    String
  attempt       Attempt  @relation(fields: [attemptId], references: [id], onDelete: Cascade)
  question      Question @relation(fields: [questionId], references: [id])
  selectedIndex Int?                              // null = dikosongkan
  updatedAt     DateTime @updatedAt
  @@unique([attemptId, questionId])
}

model Announcement {
  id          String   @id @default(cuid())
  title       String
  body        String
  isPublished Boolean  @default(false)
  createdAt   DateTime @default(now())
}

model ContentPage {                 // konten statis yang bisa diedit admin
  key       String   @id            // about | rules | contact | home_tagline | schedule | privacy
  title     String
  body      String                  // Markdown
  updatedAt DateTime @updatedAt
}

model Setting {
  key   String @id                  // registrationCloseAt, publicRankingLimit
  value Json
}

model AuditLog {
  id        String   @id @default(cuid())
  adminId   String
  admin     User     @relation(fields: [adminId], references: [id])
  action    String                  // contoh: EXAM_OPEN, RESULTS_PUBLISH, QUESTION_UPDATE
  entity    String
  entityId  String?
  meta      Json?
  createdAt DateTime @default(now())
}
```

**Seed** wajib mengisi: 3 `Level`, daftar `Subject` awal (sesuai PRD umum), `Setting` awal (`registrationCloseAt` = null, `publicRankingLimit` = null/semua), `ContentPage` awal (termasuk `privacy`), dan satu admin dengan `mustChangePassword = true`.
**Ujian tidak di-seed.** Admin membuat ujian sendiri: memilih jenjang + mapel, lalu mengisi judul, durasi, jumlah soal, jumlah pilihan, dan acak soal ya/tidak.

**Aturan konsistensi soal:**
- `optionCount` (2–5) berlaku sama untuk semua soal dalam satu ujian. Form soal menampilkan tepat sebanyak itu kolom pilihan.
- `optionCount` dan `questionCount` hanya bisa diubah selama ujian belum punya soal. Jika sudah ada soal atau attempt, field dikunci (harus hapus soal dulu atau konfirmasi eksplisit yang dicatat di audit log).
- Label pilihan di UI: A, B, C, ... dibuat dari indeks, tidak disimpan.

## 5. PENDAFTARAN & AUTH

**Form daftar** (semua wajib): nama lengkap, email, nomor WhatsApp, asal sekolah/instansi, kota/kabupaten, jenjang, mata pelajaran (**boleh lebih dari satu**, hanya mapel yang punya ujian aktif pada jenjang terpilih), password (min 8 karakter), konfirmasi password, **checkbox persetujuan data pribadi** (wajib dicentang; tautan ke halaman `/privasi`).

**Aturan:**
- Pendaftaran terbuka selama `registrationCloseAt` kosong atau `now < registrationCloseAt`. Cek **di server** saat submit, bukan hanya menyembunyikan tombol.
- Setelah tutup: halaman daftar menampilkan "Pendaftaran ditutup"; login peserta lama tetap jalan.
- Email unik. Nomor WhatsApp dinormalisasi (08xx → 628xx), **unik: satu nomor = satu akun** (nomor milik peserta sendiri). Duplikat ditolak dengan pesan jelas.
- **Normalisasi nama sekolah:** helper `normalizeText()` = Unicode NFKC, `trim`, spasi berlebih jadi satu, huruf kecil. Hasilnya disimpan di `schoolNormalized`; teks asli tetap disimpan di `school` untuk tampilan. Pencarian, filter, dan rekap per sekolah memakai `schoolNormalized`. ("SMAN 1 Sidoarjo", "sman 1 sidoarjo", "SMAN  1   Sidoarjo" dianggap sama; singkatan beda seperti "SMA Negeri 1" tidak disamakan.)
- `consentAt` diisi saat daftar. Tanpa centang, form ditolak server.
- Jenjang melekat di akun. Mapel yang dipilih harus milik jenjang itu (validasi server).
- Satu peserta boleh mendaftar **banyak mapel tanpa batas**, asal satu jenjang (satu `Registration` per mapel). Mapel tambahan bisa didaftarkan dari dashboard selama pendaftaran terbuka. Tiap mapel = ujian terpisah dengan satu kesempatan sendiri.
- `participantCode` = `OMPN26-` + nomor urut 4 digit, dibuat dalam transaksi supaya tidak bentrok.
- Login: email + password. Setelah 5 kali gagal, kunci akun **15 menit** (`failedLogins`, `lockedUntil`). Akun `isActive=false` tidak bisa login.
- Batasi endpoint daftar dan login (mis. 10 request/menit/IP). Rate limit in-memory di serverless hanya perlindungan ringan, jangan diandalkan sepenuhnya.

**Lupa password (tanpa email):**
1. Halaman `/lupa-password` hanya berisi petunjuk: hubungi panitia (kontak dari `ContentPage` kontak), sebutkan email dan kode peserta.
2. Admin mereset dari dashboard: sistem membuat password sementara acak (ditampilkan sekali ke admin), set `mustChangePassword = true`, `passwordChangedAt = now`, reset `failedLogins` dan `lockedUntil`, catat di `AuditLog`.
3. Peserta login dengan password sementara, lalu dipaksa membuat password baru.

## 6. SISTEM UJIAN (INTI PRODUK)

### 6.1 Penutupan otomatis ujian
Fungsi `ensureExamState(exam)` (dipanggil setiap exam dibaca: dashboard, ruang ujian, halaman admin, pembahasan, peringkat): jika `status == SCHEDULED` dan `now > endAt`, ubah `status` menjadi `CLOSED` (dicatat di audit log sebagai aksi sistem). Admin tetap bisa menutup lebih awal secara manual. Tombol admin "Sinkronkan status ujian" menjaring semua ujian sekaligus.

### 6.2 Syarat tombol "Mulai Ujian" aktif
Semua dicek di server:
`exam.status == SCHEDULED` **dan** `startAt <= now <= endAt` **dan** peserta terdaftar di exam itu **dan** belum ada attempt `SUBMITTED` **dan** akun aktif.

Sebelum `startAt`: tombol nonaktif + hitung mundur. Setelah `endAt` atau ujian ditutup: tombol hilang, diganti "Ujian ditutup". Server menolak permintaan mulai di luar jendela waktu walau dikirim manual. Tombol berubah aktif otomatis tanpa refresh (polling ringan atau hitung dari server time).

### 6.3 Memulai
- Server membuat `Attempt` dalam transaksi. Karena `registrationId` unik, klik ganda atau dua tab tidak membuat attempt kedua (tangkap error unik, kembalikan attempt yang ada).
- Jika `shuffleQuestions == true`, buat `questionOrder` (Fisher-Yates dengan `crypto.randomInt`) di transaksi yang sama.
- `endsAt = min(now + durationMinutes, exam.endAt)`.
- Attempt `IN_PROGRESS` yang belum lewat `endsAt`: masuk ulang = **lanjutkan attempt yang sama** (sisa waktu tidak di-reset).

### 6.4 Ruang ujian
- Satu halaman fokus (tanpa navbar utama), HP-first.
- Timer hitung mundur dari `endsAt` (offset server time dihitung saat load).
- Panel nomor soal 1..N dengan status: sudah dijawab / belum / sedang dibuka.
- Navigasi Sebelumnya / Berikutnya, lompat via nomor.
- Pilihan sebanyak `exam.optionCount` (A, B, C, ...); klik lagi pilihan yang sama = batalkan jawaban.
- Tombol **Selesai** → dialog konfirmasi berisi jumlah soal belum dijawab.
- Teks soal (HTML tersanitasi + gambar + rumus KaTeX) dan teks pilihan dirender aman.
- Urutan soal: jika `shuffleQuestions == false`, urut 1..N; jika `true`, diacak per peserta dan disimpan di `Attempt.questionOrder`. Nomor di layar = posisi dalam urutan peserta. Pilihan tidak diacak. Pembahasan memakai urutan yang sama.

### 6.5 Autosave & pengumpulan
**Autosave**
- Setiap klik jawaban memanggil `PUT /api/attempts/[id]/answer` dengan `{questionId, selectedIndex}` → **upsert** `Answer`. Server memvalidasi `selectedIndex < optionCount`.
- Server menolak (409) jika attempt sudah `SUBMITTED` atau `now > endsAt + 5 detik`.
- Client: antrean lokal untuk jawaban gagal terkirim + retry dengan backoff; indikator "Tersimpan / Menyimpan / Gagal, mencoba lagi". `localStorage` hanya antrean retry, bukan sumber kebenaran.
- Saat reload atau login ulang, jawaban diambil dari DB.

**Pengumpulan**
- `POST /api/attempts/[id]/submit` — **idempotent**: jika sudah `SUBMITTED`, kembalikan hasil lama.
- Sebelum hitung, client mengirim semua jawaban yang tertahan di antrean.
- Hitung via `gradeAttempt()` dalam satu transaksi: set `status`, `submittedAt`, `submitReason`, `correctCount`, `score`, `durationSeconds`.
- **`durationSeconds`:** untuk `MANUAL` = `submittedAt - startedAt`. Untuk `TIMEOUT` = **durasi penuh** (`endsAt - startedAt`), supaya peserta yang waktunya habis tidak tampak lebih cepat. `submittedAt` pada TIMEOUT diisi `endsAt`.
- **Auto-submit:** client memanggil submit saat timer = 0 (`TIMEOUT`).
- **Finalisasi lazy:** setiap kali attempt `IN_PROGRESS` dengan `endsAt` lewat dibaca, server memfinalisasinya (`TIMEOUT`) dengan jawaban tersimpan.
- Tombol admin **"Finalisasi semua attempt kedaluwarsa"**, wajib dijalankan sebelum publikasi hasil.
- Setelah `SUBMITTED`: layar "Jawaban terkumpul". **Nilai tidak ditampilkan** sampai admin mempublikasikan hasil.

### 6.6 Penilaian

```
correctCount = jumlah Answer.selectedIndex == Question.correctIndex
score = round((correctCount / exam.questionCount) * 100, 2)   // 2 desimal
```
Salah = 0, kosong = 0, tanpa pengurangan. Pakai `questionCount` dari exam. Unit test wajib (contoh dengan `questionCount = 30`, dan satu kasus dengan jumlah lain, mis. 20): 30/30=100, 25/30=83.33, 20/30=66.67, 15/30=50, 10/30=33.33, 0=0; 7/20=35.00.

### 6.7 Validasi sebelum ujian dijadwalkan
Admin tidak bisa mengubah status ke `SCHEDULED` jika: `startAt`/`endAt` kosong atau `endAt <= startAt`; `durationMinutes`, `questionCount`, atau `optionCount` tidak valid; jumlah soal ≠ `questionCount`; nomor soal tidak urut lengkap 1..N; ada soal yang `options.length != optionCount`, ada pilihan kosong, `correctIndex` tidak valid, atau `explanation` kosong. Tampilkan daftar masalahnya.

Setelah ada attempt, soal dan kunci **tidak boleh diedit** tanpa konfirmasi eksplisit admin (dicatat di audit log; lalu jalankan "Hitung ulang nilai ujian ini").

## 7. DASHBOARD ADMIN

Route `/admin/*`, hanya `ADMIN`. Layout sidebar, tabel dengan pencarian dan paginasi.

**A. Peserta** — daftar + cari (nama, email, kode, sekolah via `schoolNormalized`), filter jenjang/mapel, edit data, reset password (sementara, bagian 5), aktif/nonaktifkan akun, status pendaftaran, **ekspor CSV/Excel**.

**B. Soal** — pilih ujian → daftar soal 1..N; tambah/edit/hapus.
- **Editor Tiptap** untuk teks soal: tebal, miring, garis bawah, pangkat/indeks, daftar, tabel sederhana, **sisipkan gambar** (unggah ke Blob, atau paste dari clipboard; png/jpg/webp, maks 2 MB; endpoint khusus admin), **sisipkan rumus** (KaTeX).
- **Gambar hanya boleh ada di teks soal.** Editor pilihan dan editor pembahasan **tanpa tombol gambar** (formatting dasar + rumus saja), dan sanitizer server membuang tag `<img>` dari `options` dan `explanation`.
- Jumlah kolom pilihan mengikuti `exam.optionCount`; admin memilih pilihan yang benar (kunci) dan menulis pembahasan.
- **Impor CSV massal**, kolom: `jenjang, mapel, nomor, pertanyaan, a, b, c, ... (sebanyak optionCount), kunci, pembahasan`. `kunci` berupa huruf (A, B, ...). Rumus ditulis `$...$`. Impor validasi per baris, tampilkan pratinjau + daftar error, simpan setelah konfirmasi, timpa soal `(exam, nomor)` yang sama hanya jika dicentang "timpa". Gambar ditambahkan lewat editor setelah impor. Sediakan **tombol unduh template CSV** (menyesuaikan `optionCount` ujian terpilih).

**C. Ujian** — buat/ubah ujian: jenjang, mapel, judul, **durasi**, **jumlah soal**, **jumlah pilihan**, **jadwal mulai dan selesai**, **acak soal ya/tidak** (tidak bisa diubah setelah ada peserta yang mulai), status (DRAFT/SCHEDULED/CLOSED). Lihat status pengerjaan peserta (belum mulai / berlangsung / selesai, waktu mulai, sisa waktu). Aksi massal: jadwalkan/tutup semua ujian siap. Tombol "Finalisasi attempt kedaluwarsa" dan "Sinkronkan status ujian".

**D. Nilai** — hasil per ujian, lihat jawaban per peserta (jawaban vs kunci), hitung ulang, saklar **Publikasikan hasil** per ujian. Dua jenis ekspor (CSV dan Excel, hanya ADMIN, setiap ekspor dicatat di `AuditLog`):
- **Ekspor rekap nilai:** satu baris per peserta: kode, nama, sekolah, jenjang, mapel, jumlah benar, nilai, durasi, alasan submit, waktu kumpul, peringkat.
- **Ekspor jawaban peserta:** satu baris per peserta, satu kolom per nomor soal berisi huruf jawaban peserta (kosong jika tidak dijawab). Baris pertama di bawah header berisi kunci jawaban per nomor. Tersedia juga format panjang (satu baris per peserta per soal: nomor, jawaban, kunci, benar/salah) untuk analisis. Jika ujian memakai acak soal, kolom mengikuti nomor soal asli (bukan urutan peserta).
- Ekspor jawaban hanya mencakup attempt `SUBMITTED`; admin diberi peringatan jika masih ada attempt kedaluwarsa yang belum difinalisasi.

**E. Peringkat** — per jenjang+mapel, verifikasi, publikasi (sama dengan saklar hasil), batas tampil (`publicRankingLimit`, default semua).

**F. Pembahasan** — saklar Buka/Tutup per ujian (dan aksi massal). **Hanya bisa dibuka jika `exam.status == CLOSED` dan `now > exam.endAt`** (validasi server; tombol disabled diberi alasan).

**G. Konten** — edit `ContentPage` (tentang, peraturan, kontak, tagline, jadwal, privasi), kelola `Announcement`, atur `Setting` (`registrationCloseAt`, `publicRankingLimit`), kelola daftar mapel (tambah/ubah/nonaktifkan).

**H. Log aktivitas** — `AuditLog` read-only (siapa, apa, kapan).

---

## 8. PEMBAHASAN & HASIL (ATURAN AKSES)

`/dashboard/review/[examId]` hanya memuat kunci/penjelasan jika **semua** benar (dicek di server, setiap request):

1. `exam.status == CLOSED`
2. `now > exam.endAt`
3. `exam.discussionOpen == true`
4. Peserta punya attempt `SUBMITTED` di exam itu

Peserta yang selesai lebih cepat tetap terkunci sampai semua syarat terpenuhi.

Tampilan per soal: nomor, pertanyaan (+gambar, rumus), pilihan, jawaban peserta, kunci, status benar/salah, penjelasan. Semua HTML tersanitasi.

Nilai & peringkat peserta tampil hanya jika `exam.resultsPublished == true`.

**Test kebocoran wajib:** panggil semua endpoint peserta selama ujian berlangsung dan pastikan respons JSON tidak mengandung `correctIndex`/`explanation`.

## 9. PERINGKAT

- Dikelompokkan per **jenjang + mapel**, hanya attempt `SUBMITTED`.
- Peringkat **berurutan tanpa lompat: 1, 2, 3, 4, dst.** (tidak ada peringkat kembar).
- Urutan penentu:
  1. `score` tertinggi
  2. `durationSeconds` terkecil (waktu pengerjaan lebih cepat menang)
  3. `submittedAt` paling awal
  4. `attempt.id` (pemecah terakhir agar urutan deterministik)
- Hitung lewat query (`ROW_NUMBER() OVER (PARTITION BY exam ORDER BY score DESC, durationSeconds ASC, submittedAt ASC, id ASC)`), tidak disimpan permanen.
- Tampilkan Peringkat 1–3 menonjol, lalu daftar lainnya sesuai `publicRankingLimit`.
- **Peringkat hanya untuk peserta yang login** (tidak ada halaman publik). Peserta melihat posisinya sendiri + podium.
- Peserta yang tidak ikut tidak masuk peringkat.
- Aturan pemecah seri di atas dan aturan TIMEOUT = durasi penuh ditampilkan di halaman `rules` agar peserta tahu sebelum ujian.

## 12. KEAMANAN & DATA

- Password: `bcryptjs` cost ≥ 10; tidak pernah dikembalikan di respons.
- Validasi Zod di semua input. Konten editor disanitasi server (allowlist tag: p, br, strong, em, u, sub, sup, ul, ol, li, table, thead, tbody, tr, th, td, img (hanya di `text`), span/div untuk KaTeX; atribut `src` img hanya dari domain Blob proyek).
- Upload Blob hanya untuk admin, tipe png/jpg/webp, maks 2 MB.
- Cookie sesi `httpOnly`, `secure`, `sameSite=lax`. HTTPS dari Vercel.
- **Data pribadi:** persetujuan tercatat (`consentAt`), halaman `/privasi` menjelaskan data apa yang dikumpulkan dan untuk apa. Ekspor data peserta hanya admin.
- **Backup:** aktifkan point-in-time recovery di provider Postgres, sediakan script `pnpm db:backup` (pg_dump) + dokumentasi restore. Ambil backup manual setelah pendaftaran ditutup, sebelum ujian pertama dimulai, dan setelah ujian ditutup.
- Audit log untuk: ubah soal/kunci, ubah parameter ujian, buka/tutup ujian (termasuk penutupan otomatis), publikasi hasil, buka pembahasan, reset password, nonaktifkan akun, ubah setting.
- Cek batas layanan gratis (koneksi DB, storage, jam kompute, kuota Blob) sebelum ujian pertama. Beban kecil; risiko utama adalah batas koneksi → wajib pooled connection.

## 14. KRITERIA SELESAI (CHECKLIST UJI)

Poin 1–9 lulus sebelum ujian pertama dibuka; poin 10–17 lulus sebelum hasil dipublikasikan.

1. Peserta bisa daftar (dengan centang persetujuan) dan login; data tersimpan; ID peserta unik; nomor WA dan email duplikat ditolak.
2. Nama sekolah dengan huruf besar/kecil/spasi berbeda menghasilkan `schoolNormalized` yang sama.
3. Pendaftaran ditolak server setelah `registrationCloseAt` (uji dengan mengubah setting); login lama tetap bisa.
4. Peserta tidak bisa memulai ujian di luar jadwal atau saat status bukan `SCHEDULED`.
5. Ujian dengan jumlah soal, jumlah pilihan, dan durasi bervariasi (uji minimal dua konfigurasi berbeda) tampil benar; timer sesuai `endsAt`, tetap benar setelah refresh dan setelah jam perangkat diubah.
6. Jawaban tersimpan otomatis; tutup tab lalu buka lagi → jawaban dan sisa waktu utuh.
7. Dua tab/klik ganda tidak menghasilkan dua attempt atau dua hasil.
8. Waktu habis → terkumpul otomatis (durasi dicatat penuh); peserta yang menghilang terjaring finalisasi; ujian yang lewat `endAt` otomatis menjadi `CLOSED`.
9. Tidak ada respons peserta yang memuat `correctIndex`/`explanation` selama ujian berlangsung; gambar hanya ada di teks soal dan `<img>` di pilihan/pembahasan dibuang sanitizer; HTML berisi `<script>` ditolak/dibersihkan.
10. Nilai dihitung benar (kasus uji 6.6) dan tersimpan per peserta+ujian.
11. Peringkat berurutan 1, 2, 3, ... per jenjang+mapel; skor sama diurutkan berdasarkan durasi, lalu waktu kumpul paling awal.
12. Hasil/peringkat tidak terlihat sebelum admin publikasi; peringkat tidak bisa diakses tanpa login.
13. Pembahasan terkunci selama periode ujian, termasuk bagi yang selesai lebih awal, dan baru terbuka setelah syarat bagian 8 terpenuhi.
14. Peserta tidak bisa membaca data peserta lain (uji ganti ID di URL/body).
15. Admin bisa kelola peserta, ujian, soal, nilai, peringkat, pembahasan, konten tanpa ubah kode; ekspor CSV/Excel (rekap nilai dan jawaban peserta) jalan; reset password + paksa ganti password jalan.
16. Berjalan baik di HP (360px) dan desktop; HTTPS aktif.
17. Backup bisa direstore.
